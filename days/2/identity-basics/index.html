Identity Basics

AgentCore Identity solves a fundamental challenge: How do you authenticate non-human identities?

Traditional authentication is designed for users clicking login buttons. Agents need something different - they need to authenticate themselves and access resources on behalf of users.

AgentCore Identity Architecture

AgentCore Identity provides two types of authentication:

Inbound Authentication

Inbound Authentication validates who or what is invoking your agent:

  • User authentication via JWT tokens from Amazon Cognito
  • Application authentication via IAM credentials
  • API authentication via API keys

Outbound Authentication

Outbound Authentication enables your agent to securely call external services:

  • OAuth 2.0 flows (2-legged and 3-legged)
  • API Key management
  • JWT token handling

Why Both?

Inbound auth protects your agent from unauthorized access. Outbound auth enables your agent to securely access resources. Both are essential for production deployments.

Step 2: Create Your Agent

Create agent.py with your agent code (same as Day 1):

# agent.py - Your agent code (same as Day 1)
from strands import Agent, tool
from strands_tools import calculator
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands.models import BedrockModel
from datetime import datetime

app = BedrockAgentCoreApp()

@tool
def get_weather() -> str:
    """Get the current weather."""
    return "sunny"

@tool
def get_current_time() -> str:
    """Get the current date and time."""
    return datetime.now().isoformat()

model = BedrockModel(
    model_id="global.anthropic.claude-sonnet-4-20250514-v1:0",
)

agent = Agent(
    model=model,
    tools=[calculator, get_weather, get_current_time],
    system_prompt="You're a helpful assistant. You can do simple math, tell the weather, and get the time."
)

@app.entrypoint
def handle_request(payload):
    """Handle incoming requests from AgentCore Runtime."""
    user_input = payload.get("prompt")
    print(f"User input: {user_input}")
    response = agent(user_input)
    return response.message['content'][0]['text']

if __name__ == "__main__":
    app.run()

Step 3: Set Up Cognito Authentication

Create deploy_secure_agent.py to set up Cognito and deploy your agent:

# deploy_secure_agent.py - Deploy agent with JWT authentication
import time
from agentcore_course_helpers import setup_cognito, cleanup_cognito
from bedrock_agentcore_starter_toolkit import Runtime

# Step 1: Set up Cognito (creates user pool, client, and test user)
print("Setting up Cognito...")
config = setup_cognito(pool_name="Day2Pool")

print(f"\n✅ Cognito Setup Complete!")
print(f"   Discovery URL: {config['discovery_url']}")
print(f"   Client ID: {config['client_id']}")
print(f"   Test User: courseuser / CoursePassword123!")
print(f"   Bearer Token: {config['bearer_token'][:50]}...")

# Step 2: Configure AgentCore Runtime with JWT authorization
print("\n📦 Configuring AgentCore Runtime...")
agentcore_runtime = Runtime()

response = agentcore_runtime.configure(
    entrypoint="agent.py",
    auto_create_execution_role=True,
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    agent_name="secure-agent",
    authorizer_configuration={
        "customJWTAuthorizer": {
            "discoveryUrl": config["discovery_url"],
            "allowedClients": [config["client_id"]]
        }
    }
)
print("✅ Configuration complete!")

# Step 3: Deploy the agent
print("\n🚀 Deploying agent (this takes 3-5 minutes)...")

print(f"   Agent ID: {launch_result.agent_id}")

# Wait for deployment
status = agentcore_runtime.status().endpoint['status']
while status not in ['READY', 'CREATE_FAILED']:
    time.sleep(10)
    status = agentcore_runtime.status().endpoint['status']
    print(f"   Status: {status}")

if status == 'READY':
    print("✅ Agent deployed successfully!")
else:
    print("❌ Deployment failed!")
    exit(1)

# Step 4: Test invocation WITH authentication
print("\n🔐 Testing authenticated invocation...")
response = agentcore_runtime.invoke(
    {"prompt": "What is 25 * 4?"},

print(f"✅ Response: {response}")

# Save config for later use
print(f"\n📝 Save these values for invoke_agent.py:")
print(f"   POOL_ID = \"{config['pool_id']}\"")
print(f"   CLIENT_ID = \"{config['client_id']}\"")
print(f"   CLIENT_SECRET = \"{config['client_secret']}\"")

Step 4: Invoke Your Secure Agent

Create invoke_agent.py to invoke your deployed agent using the REST API with Bearer token:

# invoke_agent.py - Invoke agent with Bearer token via REST API
import requests
import urllib.parse
import json
import uuid
from agentcore_course_helpers import get_bearer_token

# Replace with values from deploy_secure_agent.py output
AGENT_ARN = "arn:aws:bedrock-agentcore:us-east-1:123456789012:agent-runtime/secure-agent"
REGION = "us-east-1"
CLIENT_ID = "your-client-id-here"
CLIENT_SECRET = "your-client-secret-here"

# Get a fresh bearer token (tokens expire after 1 hour)
print("Getting fresh bearer token...")
bearer_token = get_bearer_token(
    client_id=CLIENT_ID,
    client_secret=CLIENT_SECRET
)
print("✅ Got fresh token!")

# URL encode the agent ARN
escaped_agent_arn = urllib.parse.quote(AGENT_ARN, safe='')

# Construct the AgentCore REST API URL
url = f"https://bedrock-agentcore.{REGION}.amazonaws.com/runtimes/{escaped_agent_arn}/invocations?qualifier=DEFAULT"

# Generate a unique session ID (must be at least 33 characters)
session_id = str(uuid.uuid4())

# Set up headers with Bearer token authentication
headers = {
    "Authorization": f"Bearer {bearer_token}",
    "Content-Type": "application/json",
    "X-Amzn-Bedrock-AgentCore-Runtime-Session-Id": session_id
}

# Invoke the agent
prompt = "What time is it and what's the weather?"
print(f"\nInvoking agent: {prompt}")

response = requests.post(
    url,
    headers=headers,
    data=json.dumps({"prompt": prompt})
)

# Handle response
print(f"Status Code: {response.status_code}")

if response.status_code == 200:
    result = response.json()
    print(f"✅ Response: {json.dumps(result, indent=2)}")
else:
    print(f"❌ Error: {response.json()}")

Run it:

python invoke_agent.py

Expected output:

✅ Got fresh token!

Invoking agent: What time is it and what's the weather?
Status Code: 200
✅ Response: "The current time is 2025-01-10T14:32:15 and the weather is sunny."

Bearer Token Authentication

JWT-configured agents use the Authorization: Bearer <token> header instead of AWS SigV4 signing. This is how your web/mobile app will authenticate users calling your agent.

Without Token = AccessDenied

Try removing the bearer_token parameter - you’ll get: AccessDeniedException: Agent is configured for a different authorization token type

Identity Providers

AgentCore Identity works with any OAuth 2.0 / OIDC compliant provider:

  • Amazon Cognito (what we use in this course)
  • Auth0
  • Okta
  • Azure AD
  • Google Identity

JWT vs IAM Authentication

AgentCore Runtime supports two authentication modes:

ModeUse CaseHow It Works
JWT (OAuth)End-user authenticationUsers login → get token → call agent
IAM (SigV4)Service-to-serviceAWS roles/credentials → call agent

When to use each:

  • JWT: Web/mobile apps where humans authenticate (what we’re doing today)
  • IAM: Backend services, Lambda functions, other AWS services calling your agent

By default, AgentCore uses IAM. We configured JWT by adding authorizer_configuration.

What Happens Behind the Scenes

When a request arrives at your agent:

  1. Token Validation: AgentCore Runtime validates the JWT against Cognito’s JWKS endpoint
  2. Client Check: Verifies the token’s client_id is in your allowedClients list
  3. Expiration Check: Ensures the token hasn’t expired
  4. Forward to Agent: Valid requests reach your @app.entrypoint function
  5. Reject Invalid: Invalid tokens get AccessDeniedException before reaching your code

Your agent code stays simple - authentication happens at the runtime level!

Deep Dive: What setup_cognito() Does

Optional Reading

This section explains what the setup_cognito() helper does under the hood. Skip ahead to Your Agent Code if you want to continue building.

The helper performs three main steps:

1. Create User Pool - The identity store for your users:

cognito.create_user_pool(PoolName="Day2Pool", ...)

2. Create App Client - How your agent authenticates:

cognito.create_user_pool_client(
    UserPoolId=pool_id,
    GenerateSecret=True,  # For secure token requests
    ExplicitAuthFlows=["ALLOW_USER_PASSWORD_AUTH", ...]
)

3. Create Test User & Get Token:

cognito.admin_create_user(Username="courseuser", ...)
cognito.initiate_auth(AuthFlow="USER_PASSWORD_AUTH", ...)

The discovery URL follows this pattern:

https://cognito-idp.{region}.amazonaws.com/{pool_id}/.well-known/openid-configuration

This URL tells AgentCore where to find Cognito’s public keys for JWT validation.

Production Tip

In production, you’d use AWS CDK or CloudFormation to create Cognito resources. The helper is designed for learning and experimentation.

Hands-On: Outbound Authentication

Enable your agent to securely call external APIs using credential providers. In this example, we’ll use the GitHub API to demonstrate how credential providers work.

For Demonstration Only

This example uses a GitHub Personal Access Token (PAT) to demonstrate the @requires_api_key pattern. For production GitHub integrations, consider:

  • 3-Legged OAuth (3LO): Use @requires_access_token with USER_FEDERATION for user-authorized access
  • MCP Integration: Use the GitHub MCP Server for standardized tool access

Prerequisites

You’ll need a GitHub Personal Access Token. Create one at github.com/settings/tokens → Generate new token (classic) → Select public_repo scope.

Step 1: Create the Credential Provider

Create setup_credential_provider.py to store your API key securely:

# setup_credential_provider.py - Create API key credential provider
from bedrock_agentcore.services.identity import IdentityClient
from boto3.session import Session

boto_session = Session()
region = boto_session.region_name

print(f"Creating credential provider in {region}...")

identity_client = IdentityClient(region=region)

# Create credential provider for GitHub API
# Replace with your actual Personal Access Token
GITHUB_TOKEN = "ghp_your-github-token-here"

api_key_provider = identity_client.create_api_key_credential_provider({
    "name": "github-api-credentials",
    "apiKey": GITHUB_TOKEN
})

print(f"✅ Created credential provider!")
print(f"   Provider Name: github-api-credentials")
print(f"   Provider Details: {api_key_provider}")

Step 2: Create Agent with Outbound Auth

Create agent_outbound.py that uses the @requires_api_key decorator:

# agent_outbound.py - Agent with outbound authentication
from bedrock_agentcore.identity.auth import requires_api_key
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent, tool
from strands.models import BedrockModel
import requests

app = BedrockAgentCoreApp()

# Global variable to store retrieved API key
GITHUB_TOKEN = ""

@requires_api_key(provider_name="github-api-credentials")
async def get_api_key(*, api_key: str):
    """Retrieve API key from credential provider."""
    global GITHUB_TOKEN
    GITHUB_TOKEN = api_key
    print(f"✅ Retrieved GitHub token from credential provider")

@tool
def get_github_user(username: str) -> dict:
    """Get GitHub user profile information.

    Args:
        username: GitHub username (e.g., 'octocat', 'torvalds')

    Returns:
        dict: User profile including name, bio, and public repos count
    """
    try:
        response = requests.get(
            f'https://api.github.com/users/{username}',
            headers={
                'Authorization': f'token {GITHUB_TOKEN}',
                'Accept': 'application/vnd.github.v3+json'
            },
            timeout=10
        )
        response.raise_for_status()
        data = response.json()

        return {
            "username": data['login'],
            "name": data.get('name', 'N/A'),
            "bio": data.get('bio', 'No bio'),
            "public_repos": data['public_repos'],
            "followers": data['followers']
        }
    except requests.RequestException as e:
        return {"error": f"Failed to fetch GitHub user: {str(e)}"}

model = BedrockModel(model_id="anthropic.claude-sonnet-4-20250514-v1:0")
agent = Agent(model=model, tools=[get_github_user], system_prompt="You can look up GitHub user profiles.")

@app.entrypoint
async def handle_request(payload):
    """Handle requests with outbound authentication."""
    # Retrieve API key if not already available
    if not GITHUB_TOKEN:
        await get_api_key(api_key="")

    user_input = payload.get("prompt")
    response = agent(user_input)
    return response.message['content'][0]['text']

if __name__ == "__main__":
    app.run()

Step 3: Deploy and Add Outbound Policies

Create deploy_outbound_agent.py to deploy the agent. AgentCore will auto-create an execution role, and we’ll attach the outbound identity policies after launch:

# deploy_outbound_agent.py - Deploy agent with outbound auth
import time
import json
import boto3
from bedrock_agentcore_starter_toolkit import Runtime
from boto3.session import Session

boto_session = Session()
region = boto_session.region_name

print("📦 Configuring AgentCore Runtime...")
agentcore_runtime = Runtime()

response = agentcore_runtime.configure(
    entrypoint="agent_outbound.py",
    auto_create_execution_role=True,  # Let AgentCore create the role
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    agent_name="outbound_auth_agent"
)
print("✅ Configuration complete!")

# Launch the agent
print("\n🚀 Launching agent...")
launch_result = agentcore_runtime.launch()
print(f"   Agent ID: {launch_result.agent_id}")
print(f"   Agent ARN: {launch_result.agent_arn}")

# Get the auto-created execution role ARN
print("\n🔐 Adding outbound identity policies...")
agentcore_control_client = boto3.client('bedrock-agentcore-control', region_name=region)
runtime_response = agentcore_control_client.get_agent_runtime(
    agentRuntimeId=launch_result.agent_id
)
runtime_role_arn = runtime_response['roleArn']
role_name = runtime_role_arn.split("/")[1]
print(f"   Execution Role: {role_name}")

# Add outbound identity policies to the auto-created role
outbound_policies = {
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GetResourceAPIKey",
            "Effect": "Allow",
            "Action": ["bedrock-agentcore:GetResourceApiKey"],
            "Resource": "*"
        },
        {
            "Sid": "SecretManager",
            "Effect": "Allow",
            "Action": ["secretsmanager:GetSecretValue"],
            "Resource": "arn:aws:secretsmanager:*:*:secret:bedrock-agentcore*"
        }
    ]
}

iam_client = boto3.client('iam')
iam_client.put_role_policy(
    RoleName=role_name,
    PolicyName="OutboundIdentityPolicies",
    PolicyDocument=json.dumps(outbound_policies)
)
print("✅ Outbound policies attached!")

# Wait for deployment
print("\n⏳ Waiting for agent to be ready (3-5 minutes)...")
status = agentcore_runtime.status().endpoint['status']
while status not in ['READY', 'CREATE_FAILED']:
    time.sleep(10)
    status = agentcore_runtime.status().endpoint['status']
    print(f"   Status: {status}")

if status == 'READY':
    print("✅ Agent deployed successfully!")

    # Test invocation (user_id required for outbound auth with SigV4)
    print("\n🐙 Testing GitHub user lookup...")
    response = agentcore_runtime.invoke(
        {"prompt": "Tell me about the GitHub user 'octocat'"},
        user_id="test-user-123"
    )
    print(f"✅ Response: {response}")
else:
    print("❌ Deployment failed!")

Why user_id?

When using outbound authentication with SigV4 (IAM) inbound auth, you must provide a user_id parameter. This identifies which user the agent is acting on behalf of when retrieving credentials from the credential provider.

Credential Security

AgentCore Identity securely stores your API keys in AWS Secrets Manager. The @requires_api_key decorator retrieves credentials at runtime - your agent code never needs to hardcode sensitive credentials.

OAuth Access Tokens with Decorators

For OAuth 2.0 flows (accessing services like GitHub, Google, Slack), use the @requires_access_token decorator:

from bedrock_agentcore.identity.auth import requires_access_token

@requires_access_token(
    provider_name="github-oauth-provider",
    scopes=["repo", "read:user"],
    auth_flow="USER_FEDERATION"  # or "M2M" for machine-to-machine
)
async def access_github(*, access_token: str):
    """Access GitHub API with OAuth token."""
    headers = {"Authorization": f"Bearer {access_token}"}
    response = requests.get(
        "https://api.github.com/user",
        headers=headers
    )
    return response.json()

Decorator Parameters

ParameterDescription
provider_nameThe credential provider name
scopesOAuth2 scopes to request
auth_flow”M2M” (machine-to-machine) or “USER_FEDERATION”
on_auth_urlCallback for handling authorization URLs (3LO flows)
callback_urlOAuth2 callback URL
force_authenticationForce re-authentication

Automatic Token Management

AgentCore Identity handles the complete OAuth flow including token refresh. The decorator automatically retrieves valid tokens - your agent code doesn’t need to handle token lifecycle.

Best Practices

1. Principle of Least Privilege

Only request the scopes your agent needs:

# Good: Minimal scopes
scopes = ['repo:read', 'user:email']

# Bad: Over-permissioned
scopes = ['repo', 'admin:org', 'delete_repo']

2. Use Short-Lived Tokens

Configure token expiration appropriately:

# Recommended: Short access tokens, longer refresh tokens
oauth_config = {
    'accessTokenLifetime': 3600,      # 1 hour
    'refreshTokenLifetime': 2592000,  # 30 days
}

3. Audit Everything

Enable CloudTrail logging for identity operations:

# All identity operations are automatically logged to CloudTrail
# Access logs via:
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=bedrock-agentcore-identity.amazonaws.com
