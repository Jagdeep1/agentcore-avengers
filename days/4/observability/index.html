Daily Challenge

Observability

Guardrails prevent problems. Observability lets you see when they happen, understand why, and fix them before users notice.

When you deploy agents to AgentCore Runtime, you get comprehensive observability through CloudWatch GenAI Observability—traces showing every step of agent execution, metrics for performance monitoring, and logs for debugging.

Prerequisites

Before starting, ensure you have:

  • Python 3.10+ installed
  • AWS credentials configured with appropriate permissions
  • Amazon CloudWatch access in your AWS account
  • Transaction Search enabled on CloudWatch (we’ll cover this in Step 3)

Install the required dependencies:

pip install strands-agents strands-agents-tools boto3 bedrock-agentcore bedrock-agentcore-starter-toolkit aws-opentelemetry-distro~=0.12.1

Observability Architecture

Local Development

During local development, you run and test your agent directly. No observability infrastructure is needed yet—you’re focused on getting the agent logic right.

Runtime Deployment

When deployed to AgentCore Runtime, your agent automatically gets:

  • OpenTelemetry instrumentation via aws-opentelemetry-distro
  • Trace collection to CloudWatch
  • GenAI Observability dashboard integration

The Three Pillars

Traces answer “What happened in this specific request?”

  • Request → Tool Call → Model Invocation → Response
  • Timing breakdown for each step
  • Full visibility into agent decision-making

Metrics answer “How is the system performing overall?”

  • Latency: p50, p95, p99 percentiles
  • Invocation counts
  • Error rates

Logs provide “Details and context”

  • Runtime logs from your agent code
  • Error details for debugging
  • Structured data for analysis

Step 1: Local Agent Development

Start by creating and testing your agent locally. This lets you experiment without deploying.

Create observable_agent_local.py:

#!/usr/bin/env python3
"""Local agent for experimentation before deployment"""
from strands import Agent, tool
from strands_tools import calculator
from strands.models import BedrockModel
import argparse
import json

@tool
def weather():
    """Get weather"""
    return "sunny"

model_id = "us.anthropic.claude-haiku-4-5-20251001-v1:0"
model = BedrockModel(model_id=model_id)

agent = Agent(
    model=model,
    tools=[calculator, weather],
    system_prompt="You're a helpful assistant. You can do simple math calculation, and tell the weather."
)

def invoke_agent(payload):
    user_input = payload.get("prompt")
    response = agent(user_input)
    return response.message['content'][0]['text']

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("payload", type=str)
    args = parser.parse_args()
    response = invoke_agent(json.loads(args.payload))
    print(response)

Test locally:

python observable_agent_local.py '{"prompt": "What is the weather now?"}'

Expected output:

The weather is currently sunny!

Test the calculator:

python observable_agent_local.py '{"prompt": "What is 25 * 17?"}'

Expected output:

25 * 17 = 425

Local First

Always develop and test locally before deploying to Runtime. It’s faster to iterate and debug.

Step 2: Prepare for AgentCore Runtime

Now adapt your agent for Runtime deployment. The key changes are:

  1. Import and initialize BedrockAgentCoreApp
  2. Decorate your handler with @app.entrypoint
  3. Call app.run() in main

Create observable_agent_runtime.py:

#!/usr/bin/env python3
"""Agent prepared for AgentCore Runtime deployment"""
from strands import Agent, tool
from strands_tools import calculator
from strands.models import BedrockModel
from bedrock_agentcore.runtime import BedrockAgentCoreApp

app = BedrockAgentCoreApp()

@tool
def weather():
    """Get weather"""
    return "sunny"

model_id = "us.anthropic.claude-haiku-4-5-20251001-v1:0"
model = BedrockModel(model_id=model_id)

agent = Agent(
    model=model,
    tools=[calculator, weather],
    system_prompt="You're a helpful assistant. You can do simple math calculation, and tell the weather."
)

@app.entrypoint
def handle_request(payload):
    """Agent entrypoint with automatic tracing."""
    user_input = payload.get("prompt")
    print("User input:", user_input)
    response = agent(user_input)
    return response.message['content'][0]['text']

if __name__ == "__main__":
    app.run()

What BedrockAgentCoreApp Does

When you use BedrockAgentCoreApp, it automatically:

  • Creates an HTTP server listening on port 8080
  • Implements /invocations endpoint for agent requests
  • Implements /ping endpoint for health checks
  • Handles proper content types and response formats
  • Integrates with OpenTelemetry for tracing

Step 3: Enable CloudWatch Transaction Search

Before deploying, enable Transaction Search in CloudWatch to view traces.

  1. Navigate to AWS Console → CloudWatch → Settings → Traces and logs
  2. Enable “Transaction Search”
  3. Select “Ingest spans as structured logs in OpenTelemetry format”

This is required for traces to appear in the GenAI Observability dashboard.

Enable Transaction Search First

Without Transaction Search enabled, your traces won’t appear in the dashboard even though the agent is instrumented correctly.

Step 4: Deploy to AgentCore Runtime

Create requirements.txt with your dependencies:

strands-agents
strands-agents-tools
boto3
bedrock-agentcore
bedrock-agentcore-starter-toolkit
aws-opentelemetry-distro~=0.12.1

Create deploy_agent.py:

#!/usr/bin/env python3
"""Deploy agent to AgentCore Runtime"""
from bedrock_agentcore_starter_toolkit import Runtime
from boto3.session import Session

boto_session = Session()
region = boto_session.region_name

agentcore_runtime = Runtime()
agent_name = "observable_strands_agent"

# Configure deployment
response = agentcore_runtime.configure(
    entrypoint="observable_agent_runtime.py",
    auto_create_execution_role=True,
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    region=region,
    agent_name=agent_name,
    memory_mode='NO_MEMORY'
)
print("Configuration:", response)

# Launch to AgentCore Runtime
launch_result = agentcore_runtime.launch()
print("Launch result:", launch_result)

Run the deployment:

python deploy_agent.py

The deployment process:

  1. Configure - Generates Dockerfile, validates settings
  2. CodeBuild - Builds container image in AWS (no local Docker needed)
  3. ECR - Pushes image to Amazon ECR
  4. AgentCore - Creates the runtime with observability enabled

Automatic Instrumentation

The starter toolkit automatically adds OpenTelemetry instrumentation to your container:

CMD ["opentelemetry-instrument", "python", "observable_agent_runtime.py"]

Step 5: Check Deployment Status

Wait for the runtime to reach READY status.

Create check_status.py:

#!/usr/bin/env python3
"""Check AgentCore Runtime status using boto3"""
import boto3
import yaml
from pathlib import Path
import time

# Load config
config_path = Path(__file__).parent / ".bedrock_agentcore.yaml"
with open(config_path) as f:
    config = yaml.safe_load(f)

default_agent = config['default_agent']
agent_config = config['agents'][default_agent]
agent_id = agent_config['bedrock_agentcore']['agent_id']
region = agent_config['aws']['region']

print(f"Checking status for agent: {agent_id}")

# Get status via boto3
client = boto3.client('bedrock-agentcore-control', region_name=region)

response = client.get_agent_runtime(agentRuntimeId=agent_id)
status = response['status']

end_status = ['READY', 'CREATE_FAILED', 'DELETE_FAILED', 'UPDATE_FAILED']
while status not in end_status:
    time.sleep(10)
    response = client.get_agent_runtime(agentRuntimeId=agent_id)
    status = response['status']
    print(f"Status: {status}")

print(f"Final status: {status}")

Run it:

python check_status.py

Expected output:

Checking status for agent: observable_strands_agent-CtVKj2Dpe2
Final status: READY

Step 6: Invoke the Agent

Once the agent is READY, invoke it to generate traces.

Create invoke_agent.py:

#!/usr/bin/env python3
"""Invoke agent on AgentCore Runtime using boto3"""
import boto3
import yaml
import json
from pathlib import Path

# Load config
config_path = Path(__file__).parent / ".bedrock_agentcore.yaml"
with open(config_path) as f:
    config = yaml.safe_load(f)

default_agent = config['default_agent']
agent_config = config['agents'][default_agent]
agent_arn = agent_config['bedrock_agentcore']['agent_arn']
region = agent_config['aws']['region']

print(f"Invoking agent: {agent_arn}")

# Invoke via boto3
client = boto3.client('bedrock-agentcore', region_name=region)

response = client.invoke_agent_runtime(
    agentRuntimeArn=agent_arn,
    qualifier="DEFAULT",
    payload=json.dumps({"prompt": "How is the weather now?"})
)

# Process response
if "text/event-stream" in response.get("contentType", ""):
    content = []
    for line in response["response"].iter_lines(chunk_size=1):
        if line:
            line = line.decode("utf-8")
            if line.startswith("data: "):
                line = line[6:]
                content.append(line)
    print("Response:", "\n".join(content))
else:
    events = []
    for event in response.get("response", []):
        events.append(event)
    if events:
        print("Response:", json.loads(events[0].decode("utf-8")))

Run it:

python invoke_agent.py

Expected output:

Invoking agent: arn:aws:bedrock-agentcore:us-east-1:123456789:runtime/observable_strands_agent-CtVKj2Dpe2
Response: The weather is currently sunny! Great day for outdoor activities.

Generate Multiple Traces

Invoke the agent several times with different prompts to generate trace data for the dashboard.

Step 7: View Traces in GenAI Observability

Now view your traces in the CloudWatch GenAI Observability dashboard.

Navigate to the Dashboard

  1. Go to AWS Console → CloudWatch
  2. Select Application Signals → GenAI Observability
  3. Or use the direct URL: https://console.aws.amazon.com/cloudwatch/home?region=us-east-1#gen-ai-observability/agent-core

Dashboard Overview

The GenAI Observability dashboard shows:

Runtime Metrics (All Agents)

  • Latency distribution across all your agents
  • Invocation counts over time
  • Error rates

Agent-Specific View

  • Click on your agent to see metrics for just that agent
  • Filter by time range to focus on specific periods

Sessions View

  • See all sessions associated with your agent
  • Track conversation flows

Trace View

  • Detailed trace information for each invocation
  • Span breakdown showing:
    • Tool invocations with timing
    • Model calls with token counts
    • Error details if any occurred

What Traces Show

Each trace includes:

  • Request timing - Total duration and breakdown by step
  • Tool calls - Which tools were invoked and how long each took
  • Model invocations - Input/output token counts, latency
  • Errors - Stack traces and error messages for debugging

Advanced: Custom Metrics

Beyond automatic traces, you can publish custom CloudWatch metrics.

import boto3
from datetime import datetime

cloudwatch = boto3.client('cloudwatch', region_name='us-east-1')

def publish_agent_metrics(duration_ms: float, tokens: int, tool_calls: int):
    """Publish custom metrics from agent invocation."""

    metrics = [
        {
            'MetricName': 'RequestLatency',
            'Value': duration_ms,
            'Unit': 'Milliseconds',
            'Timestamp': datetime.now(),
            'Dimensions': [
                {'Name': 'AgentName', 'Value': 'observable_strands_agent'}
            ]
        },
        {
            'MetricName': 'TokensUsed',
            'Value': tokens,
            'Unit': 'Count',
            'Timestamp': datetime.now(),
            'Dimensions': [
                {'Name': 'AgentName', 'Value': 'observable_strands_agent'}
            ]
        },
        {
            'MetricName': 'ToolCalls',
            'Value': tool_calls,
            'Unit': 'Count',
            'Timestamp': datetime.now(),
            'Dimensions': [
                {'Name': 'AgentName', 'Value': 'observable_strands_agent'}
            ]
        }
    ]

    cloudwatch.put_metric_data(
        Namespace='AgentCore/CustomMetrics',
        MetricData=metrics
    )

Advanced: CloudWatch Alarms

Set up alarms for critical thresholds.

cloudwatch = boto3.client('cloudwatch', region_name='us-east-1')

# High latency alarm
cloudwatch.put_metric_alarm(
    AlarmName='AgentCore-HighLatency',
    ComparisonOperator='GreaterThanThreshold',
    EvaluationPeriods=2,
    MetricName='RequestLatency',
    Namespace='AgentCore/CustomMetrics',
    Period=300,
    Statistic='Average',
    Threshold=5000,  # 5 seconds
    ActionsEnabled=True,
    AlarmActions=['arn:aws:sns:us-east-1:123456789:agent-alerts'],
    AlarmDescription='Alert when request latency exceeds 5s',
    Dimensions=[
        {'Name': 'AgentName', 'Value': 'observable_strands_agent'}
    ]
)

Cleanup

When you’re done testing, clean up the resources.

Create cleanup_agent.py:

#!/usr/bin/env python3
"""Cleanup AgentCore Runtime resources using boto3"""
import boto3
import yaml
from pathlib import Path

# Load config
config_path = Path(__file__).parent / ".bedrock_agentcore.yaml"
with open(config_path) as f:
    config = yaml.safe_load(f)

default_agent = config['default_agent']
agent_config = config['agents'][default_agent]
agent_id = agent_config['bedrock_agentcore']['agent_id']
ecr_repository = agent_config['aws']['ecr_repository'].split('/')[1]
region = agent_config['aws']['region']

print(f"Cleaning up agent: {agent_id}")
print(f"ECR repository: {ecr_repository}")

# Create clients
agentcore_client = boto3.client('bedrock-agentcore-control', region_name=region)
ecr_client = boto3.client('ecr', region_name=region)

# Delete runtime
print(f"Deleting agent runtime...")
agentcore_client.delete_agent_runtime(agentRuntimeId=agent_id)
print(f"Agent runtime deleted")

# Delete ECR repository
print(f"Deleting ECR repository...")
ecr_client.delete_repository(repositoryName=ecr_repository, force=True)
print(f"ECR repository deleted")

print("\nCleanup complete!")

Run it:

python cleanup_agent.py
