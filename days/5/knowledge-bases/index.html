Knowledge Bases

Knowledge Bases turn your agents from models that make things up into agents that reference your data. This is Retrieval-Augmented Generation (RAG).

What is RAG?

Traditional LLM:
  User: "What were Apple's risk factors in 2024?"
  LLM: *Generates plausible-sounding but potentially inaccurate response*

RAG-Powered Agent:
  User: "What were Apple's risk factors in 2024?"
  Agent: 1. Searches Knowledge Base for relevant documents
         2. Retrieves actual excerpts from Apple's 10-K filing
         3. Generates response grounded in retrieved facts
         4. Includes citations to source documents

S3 Vectors vs OpenSearch

This course uses S3 Vectors for vector storage - AWS’s newer, simpler approach that doesn’t require managing OpenSearch clusters. S3 Vectors is serverless and automatically scales.

KB vs Fine-tuning

Knowledge Bases are for facts and reference data. Fine-tuning changes model behavior. Most production systems use Knowledge Bases, not fine-tuning.

Setting Up Your Knowledge Base

We’ll create everything programmatically using a single Python script. This approach uses S3 Vectors for vector storage - AWS’s newer, simpler alternative to OpenSearch Serverless.

Prerequisites

  1. AWS credentials configured (aws sts get-caller-identity)
  2. boto3 >= 1.34.0 (for S3 Vectors support)
  3. SEC filings downloaded (we’ll do this first)

File Size Limit

Files must be under 1MB for reliable ingestion. Larger files will fail. We’ll truncate the SEC filings to ~800KB.

Step 1: Download and Prepare SEC Filings

SEC’s EDGAR (Electronic Data Gathering, Analysis, and Retrieval) system provides free access to company filings:

# download_sec_filings.py
import requests
import os

# SEC requires User-Agent header
HEADERS = {
    'User-Agent': 'AgentCore Course contact@example.com'
}

# Sample 10-K filings (annual reports) - VERIFIED ACCESSION NUMBERS
FILINGS = [
    {
        'company': 'Apple',
        'ticker': 'AAPL',
        'cik': '0000320193',
        'accession': '0000320193-25-000079',  # FY2024 10-K
        'form': '10-K'
    },
    {
        'company': 'Microsoft',
        'ticker': 'MSFT',
        'cik': '0000789019',
        'accession': '0000950170-25-100235',  # FY2024 10-K
        'form': '10-K'
    },
    {
        'company': 'Amazon',
        'ticker': 'AMZN',
        'cik': '0001018724',
        'accession': '0001018724-25-000004',  # 2024 10-K
        'form': '10-K'
    }
]

def download_filing(filing: dict, output_dir: str = './filings'):
    """Download SEC filing from EDGAR."""
    os.makedirs(output_dir, exist_ok=True)

    # Construct EDGAR URL
    cik = filing['cik'].lstrip('0')
    accession_no_dashes = filing['accession'].replace('-', '')

    url = f"https://www.sec.gov/Archives/edgar/data/{cik}/{accession_no_dashes}/{filing['accession']}.txt"

    response = requests.get(url, headers=HEADERS)

    if response.status_code == 200:
        filename = f"{filing['ticker']}_{filing['form']}.txt"
        filepath = os.path.join(output_dir, filename)

        with open(filepath, 'w') as f:
            f.write(response.text)

        print(f"Downloaded: {filename}")
        return filepath
    else:
        print(f"Failed to download {filing['ticker']}: {response.status_code}")
        return None

# Download all filings
for filing in FILINGS:
    download_filing(filing)

EDGAR Rate Limits

SEC limits requests to 10 per second. Add delays between downloads in production.

Truncate large files (SEC filings are typically 9-30MB):

# Truncate to ~800KB for reliable ingestion
cd filings
for f in *.txt; do
    head -c 800000 "$f" > "${f%.txt}_truncated.txt"
    mv "${f%.txt}_truncated.txt" "$f"
done

Or in Python:

# truncate_filings.py
from pathlib import Path

filings_dir = Path('./filings')
MAX_SIZE = 800_000  # 800KB

for filepath in filings_dir.glob('*.txt'):
    content = filepath.read_text()
    if len(content.encode('utf-8')) > MAX_SIZE:
        # Truncate to MAX_SIZE bytes
        truncated = content.encode('utf-8')[:MAX_SIZE].decode('utf-8', errors='ignore')
        filepath.write_text(truncated)
        print(f"Truncated: {filepath.name}")
    else:
        print(f"OK: {filepath.name}")

Step 2: Create Knowledge Base Infrastructure

We provide a helper script that creates all resources automatically. First, download it from the course repository:

What the script creates

The script automatically creates: S3 bucket, uploads filings, IAM role, S3 Vectors storage, Knowledge Base, data source, runs ingestion, and stores IDs in SSM Parameter Store.

The script performs these 8 steps:

s3.create_bucket(
    Bucket=DATA_BUCKET_NAME,
    CreateBucketConfiguration={'LocationConstraint': REGION}
)

# Block public access
s3.put_public_access_block(
    Bucket=DATA_BUCKET_NAME,
    PublicAccessBlockConfiguration={
        'BlockPublicAcls': True,
        'IgnorePublicAcls': True,
        'BlockPublicPolicy': True,
        'RestrictPublicBuckets': True

)

2.2: Upload SEC Filings

for f in filings_dir.glob("*.txt"):
    s3.upload_file(
        str(f),
        DATA_BUCKET_NAME,
        f"filings/{f.name}",
        ExtraArgs={'ContentType': 'text/plain'}

2.3: Create IAM Role for Bedrock

trust_policy = {
    "Version": "2012-10-17",

iam.create_role(

# Attach permissions for S3, Bedrock, and S3 Vectors
permissions_policy = {
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",

            "Resource": [f"arn:aws:s3:::{DATA_BUCKET_NAME}/*"]
        },
        {
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": f"arn:aws:bedrock:{REGION}::foundation-model/amazon.titan-embed-text-v2:0"
        },
        {
            "Effect": "Allow",
            "Action": ["s3vectors:*"],
            "Resource": "*"
        }
    ]

2.4: Create S3 Vectors Storage

# Create vector bucket
s3vectors.create_vector_bucket(
    vectorBucketName=VECTOR_BUCKET_NAME,
    encryptionConfiguration={'sseType': 'AES256'}
)

# Create vector index with Titan embed dimensions
s3vectors.create_index(
    vectorBucketName=VECTOR_BUCKET_NAME,
    indexName=VECTOR_INDEX_NAME,
    dimension=1024,           # Titan Embed v2 dimensions
    distanceMetric='cosine',  # Similarity metric
    dataType='float32'
)

index_arn = f"arn:aws:s3vectors:{REGION}:{ACCOUNT_ID}:bucket/{VECTOR_BUCKET_NAME}/index/{VECTOR_INDEX_NAME}"

Why S3 Vectors?

S3 Vectors is serverless vector storage that doesn’t require managing OpenSearch clusters. It automatically scales and integrates directly with Bedrock Knowledge Bases.

2.5: Create Knowledge Base

kb_response = bedrock_agent.create_knowledge_base(
    name=KB_NAME,
    description='SEC 10-K filings for financial analysis',
    roleArn=role_arn,
    knowledgeBaseConfiguration={
        'type': 'VECTOR',
        'vectorKnowledgeBaseConfiguration': {
            'embeddingModelArn': f'arn:aws:bedrock:{REGION}::foundation-model/amazon.titan-embed-text-v2:0',
            'embeddingModelConfiguration': {
                'bedrockEmbeddingModelConfiguration': {
                    'dimensions': 1024,
                    'embeddingDataType': 'FLOAT32'
                }
            }
        }
    },
    storageConfiguration={
        'type': 'S3_VECTORS',
        's3VectorsConfiguration': {
            'indexArn': index_arn
        }
    }
)

KB_ID = kb_response['knowledgeBase']['knowledgeBaseId']

2.6: Create Data Source

ds_response = bedrock_agent.create_data_source(
    knowledgeBaseId=KB_ID,
    name=DATASOURCE_NAME,
    dataSourceConfiguration={
        'type': 'S3',
        's3Configuration': {
            'bucketArn': f'arn:aws:s3:::{DATA_BUCKET_NAME}',
            'inclusionPrefixes': ['filings/']
        }
    },
    vectorIngestionConfiguration={
        'chunkingConfiguration': {
            'chunkingStrategy': 'FIXED_SIZE',
            'fixedSizeChunkingConfiguration': {
                'maxTokens': 200,
                'overlapPercentage': 10
            }
        }
    }
)

DATA_SOURCE_ID = ds_response['dataSource']['dataSourceId']

2.7: Start Ingestion Job

job = bedrock_agent.start_ingestion_job(
    knowledgeBaseId=KB_ID,
    dataSourceId=DATA_SOURCE_ID
)

# Poll until complete
while True:
    status = bedrock_agent.get_ingestion_job(
        knowledgeBaseId=KB_ID,
        dataSourceId=DATA_SOURCE_ID,
        ingestionJobId=job['ingestionJob']['ingestionJobId']
    )

    state = status['ingestionJob']['status']
    stats = status['ingestionJob'].get('statistics', {})
    print(f"Status: {state} | Indexed: {stats.get('numberOfNewDocumentsIndexed', 0)}")

    if state in ['COMPLETE', 'FAILED']:
        break
    time.sleep(30)

2.8: Store IDs in Parameter Store

ssm.put_parameter(
    Name=f"/sec-filings-kb/{UNIQUE_ID}/knowledge-base-id",
    Value=KB_ID,
    Type='String',
    Overwrite=True

Querying the Knowledge Base

After the infrastructure script completes, you can query your Knowledge Base using the APIs below.

RetrieveAndGenerate API

The simplest way - retrieves relevant chunks AND generates a response:

import boto3
import os

REGION = os.environ.get('AWS_REGION', 'us-west-2')

bedrock_agent_runtime = boto3.client('bedrock-agent-runtime', region_name=REGION)

# Get KB_ID from environment or config
KB_ID = os.environ.get('KB_ID', 'your-knowledge-base-id')

# Use cross-region inference profile (recommended for production)
MODEL_ARN = f"arn:aws:bedrock:{REGION}::inference-profile/us.anthropic.claude-3-5-haiku-20241022-v1:0"

def query_knowledge_base(query: str) -> dict:
    """Query KB with RetrieveAndGenerate."""

    config = {
        'type': 'KNOWLEDGE_BASE',
        'knowledgeBaseConfiguration': {
            'knowledgeBaseId': KB_ID,
            'modelArn': MODEL_ARN,
            'retrievalConfiguration': {
                'vectorSearchConfiguration': {
                    'numberOfResults': 5
                }
            }
        }
    }

    response = bedrock_agent_runtime.retrieve_and_generate(
        input={'text': query},
        retrieveAndGenerateConfiguration=config
    )

    return {
        'response': response['output']['text'],
        'citations': response.get('citations', [])
    }

# Example usage
result = query_knowledge_base("What are Apple's main risk factors?")

print("Response:", result['response'])
print("\nCitations:")
for citation in result['citations']:
    for ref in citation.get('retrievedReferences', []):
        print(f"  - {ref['location']['s3Location']['uri']}")

Inference Profiles

We use cross-region inference profiles (e.g., us.anthropic.claude-3-5-haiku-20241022-v1:0) instead of foundation model ARNs. This provides better availability and automatic routing across regions.

Retrieve-Only API

When you need more control over response generation (useful for custom prompts or multi-step reasoning):

def retrieve_only(query: str, top_k: int = 5) -> list:
    """Retrieve chunks without generating a response."""

    retrieval_config = {
        'vectorSearchConfiguration': {
            'numberOfResults': top_k
        }
    }

    response = bedrock_agent_runtime.retrieve(
        knowledgeBaseId=KB_ID,
        retrievalQuery={'text': query},
        retrievalConfiguration=retrieval_config
    )

    chunks = []
    for result in response['retrievalResults']:
        chunks.append({
            'text': result['content']['text'],
            'score': result['score'],
            'location': result['location']['s3Location']['uri'],
            'metadata': result.get('metadata', {})
        })

    return chunks

# Example: Get raw chunks for custom processing
chunks = retrieve_only("revenue growth", top_k=3)
for chunk in chunks:
    print(f"Score: {chunk['score']:.3f}")
    print(f"Text: {chunk['text'][:200]}...")
    print()

Building the KB Retrieval Tool

Now we’ll create a Strands tool that wraps our Knowledge Base. This tool will be used in the next section when we build the Extract Agent - it allows the agent to query SEC filings as part of its data gathering capabilities.

Why a Tool?

By wrapping the KB in a Strands tool, our agent can decide when to query SEC filings based on the user’s request. The agent orchestrates multiple tools (market data, SEC filings, etc.) to gather comprehensive information.

# kb_tool.py
import boto3
import os
from strands.tools import tool

REGION = os.environ.get('AWS_REGION', 'us-west-2')

bedrock_agent_runtime = boto3.client('bedrock-agent-runtime', region_name=REGION)

# Load from environment - set these before running your agent
KB_ID = os.environ.get('KB_ID')
MODEL_ARN = f"arn:aws:bedrock:{REGION}::inference-profile/us.anthropic.claude-3-5-haiku-20241022-v1:0"

@tool
def query_sec_filings(query: str) -> str:
    """Query SEC filings from the Knowledge Base for financial information.

    Use this tool to find information from company SEC filings including:
    - 10-K annual reports (financials, risk factors, business description)
    - 10-Q quarterly reports
    - Revenue, earnings, and other financial metrics
    - Risk factors and management discussion

    Args:
        query: The question to answer from SEC filings

    Returns:
        Answer generated from SEC filings with citations
    """
    if not KB_ID:
        return "Error: KB_ID environment variable not set"

    config = {
        'type': 'KNOWLEDGE_BASE',
        'knowledgeBaseConfiguration': {
            'knowledgeBaseId': KB_ID,
            'modelArn': MODEL_ARN,
            'retrievalConfiguration': {
                'vectorSearchConfiguration': {
                    'numberOfResults': 5
                }
            }
        }
    }

    try:
        response = bedrock_agent_runtime.retrieve_and_generate(
            input={'text': query},
            retrieveAndGenerateConfiguration=config
        )

        answer = response['output']['text']

        # Add citation info
        citations = []
        for citation in response.get('citations', []):
            for ref in citation.get('retrievedReferences', []):
                uri = ref['location']['s3Location']['uri']
                citations.append(uri.split('/')[-1])

        if citations:
            answer += f"\n\nSources: {', '.join(set(citations))}"

        return answer

    except Exception as e:
        return f"Error querying SEC filings: {str(e)}"

Usage in the Extract Agent (next section):

from strands import Agent
from kb_tool import query_sec_filings

# The agent will use this tool alongside market data tools
agent = Agent(
    model=model,
    tools=[query_sec_filings, get_market_data, ...],
    system_prompt="You are a financial analyst..."
)

Best Practices

1. Chunking Strategy

Choose based on file size and requirements:

StrategyMax File SizeBest For
FIXED_SIZENo hard limitLarge files (SEC filings, reports)
SEMANTIC1 MBSmall files with clear structure
HIERARCHICALVariesDocuments with nested sections
# For SEC filings and large documents (RECOMMENDED)
# Files must be under 1MB - truncate larger files first
chunking_config = {
    'chunkingStrategy': 'FIXED_SIZE',
    'fixedSizeChunkingConfiguration': {
        'maxTokens': 200,        # Smaller chunks for better retrieval
        'overlapPercentage': 10  # 10% overlap for context continuity
    }
}

# For small files under 1MB only
chunking_config = {
    'chunkingStrategy': 'SEMANTIC',  # Has 1MB file size limit!
    'semanticChunkingConfiguration': {
        'maxTokens': 512,
        'bufferSize': 0,
        'breakpointPercentileThreshold': 95
    }
}

File Size Limits

SEMANTIC chunking requires files under 1MB. SEC filings are typically 9-30MB. Truncate large files before ingestion: head -c 800000 file.txt > file_truncated.txt

2. Metadata Filtering

Always use metadata for better retrieval:

# Filter by multiple attributes
filter_config = {
    'andAll': [
        {'equals': {'key': 'ticker', 'value': 'AAPL'}},
        {'equals': {'key': 'form', 'value': '10-K'}},
        {'greaterThan': {'key': 'year', 'value': 2022}}
    ]
}

3. Retrieval Tuning

# Adjust number of results based on query type
retrieval_config = {
    'vectorSearchConfiguration': {
        'numberOfResults': 10,  # More for broad queries
        'overrideSearchType': 'HYBRID'  # Combine semantic + keyword
    }
}

KB Sync

Remember to re-sync your data source whenever you add or update documents. Ingestion jobs can take several minutes for large document sets.
